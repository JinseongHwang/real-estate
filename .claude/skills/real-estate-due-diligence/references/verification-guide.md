# 검증 가이드

수집한 정보를 리포트에 올리기 전에 이 문서의 규칙으로 걸러낸다.
조사 에이전트와 리포트 작성자(오케스트레이터) 모두에게 적용된다.

## 1. Fact / Interpretation / Hypothesis

모든 서술을 세 가지 중 하나로 분류하고, 리포트에서 섞이지 않게 한다.

- **Fact**: 확인된 사실. 출처와 기준일이 있다.
- **Interpretation**: 사실을 기반으로 한 분석. "~로 해석된다", "~를 시사한다"처럼 분석임이 드러나게 쓴다.
- **Hypothesis**: 아직 검증되지 않은 가설. "~일 가능성이 있다. 확인 필요"처럼 가설임을 명시한다.

## 2. 불확실성 상태 5단계

각 정보에 다음 상태 중 하나를 부여한다.

| 상태 | 기준 |
|---|---|
| `확정` | A등급 원문에서 직접 확인 |
| `높은 신뢰` | B등급 이상 복수 출처가 일치 |
| `참고` | 단일 출처(C/D등급)만 확인. 방향성 참고용 |
| `추정` | 데이터에서 유도한 계산/판단. 근거를 함께 표기 |
| `확인 필요` | 확인하지 못했거나 출처 간 충돌이 해소되지 않음 |

나쁜 예: "방배동 OO구역은 재건축이 진행 중이다."
좋은 예: "정비사업 정보몽땅 기준 OO구역은 현재 사업시행인가 단계로 확인된다(2026-08 기준).
향후 일정은 변동될 수 있으므로 매수 판단 시 진행 속도를 별도로 확인해야 한다."

## 3. 기준일 표기

시간에 민감한 모든 정보에 기준일을 붙인다. 특히 실거래, 매물/호가, 금리, 정책, 규제,
정비사업 단계, 교통사업, 뉴스, 전월세는 예외 없이 `YYYY-MM 기준` 또는 `YYYY-MM-DD 기준`으로 쓴다.
자료 자체의 기준일과 열람일이 다르면 자료 기준일을 우선 표기한다.

## 4. 교차검증 절차

1. 핵심 주장(매수 판단을 좌우하는 것)을 골라낸다.
2. 원 출처와 독립된 다른 출처에서 재확인한다. 같은 기사를 베낀 매체들은 독립 출처가 아니다.
3. 원 출처의 성격을 의심한다: 오래됐는가, 홍보성인가, 이해관계자(조합, 분양대행)가 낸 자료인가.
4. 재확인에 실패하면 상태를 `확인 필요`로 낮춘다. 억지로 유지하지 않는다.

## 5. 데이터 충돌 처리

예. 호갱노노 15억 / 국토부 실거래 14.5억 / 네이버 15.2억이라면 하나를 임의로 고르지 않는다.

- 각 숫자의 성격을 구분한다: 실거래가(실제 계약), 호가(매도 희망가), 추정가(알고리즘 산출).
- 집계 기준 차이(기간, 평형, 층, 거래 취소 반영 여부)를 확인한다.
- 리포트에는 구분해서 싣고, 차이가 왜 나는지 설명한다. 판단의 기준값은 공식 실거래가다.

## 6. 가격 분석 방법

"현재 15억 → 비싸다" 같은 단정을 금지한다. 세 층위로 분석한다.

1. **절대 가격**: 최근 실거래(복수), 현재 호가 범위, 과거 최고가/최저가, 최고가 대비 현재 수준
2. **상대 가격**: 같은 동네, 인근 동네, 같은 역세권, 비슷한 연식/세대수/평형과 비교
3. **상품 비교**: 가격 차이의 원인 분해. "왜 A가 B보다 1억 비싼가"를 연식, 역거리, 세대수, 학군, 정비 기대감 등으로 설명

전세가율은 실수요 강도의 참고 지표로 쓰되, 단독으로 결론 내지 않는다.

## 7. 협상 구간 (해당 시)

매수 후보 단지라면 최근 거래, 최근 저가 거래, 현재 호가, 최고가, 거래량, 매물 적체,
동일 단지 다른 평형, 인근 단지 가격을 근거로 적정 협상 구간을 제시할 수 있다.
반드시 추정임을 명시한다.

좋은 예: "최근 실거래와 현재 호가를 고려하면 14.5~15억 수준에서 협상 가능성을 검토할 수 있으나,
실제 협상 가능 가격은 매도자의 상황에 따라 달라질 수 있다(추정, 2026-08 기준)."

## 8. 개발/정비 호재 검증

- 사업 단계를 확인하기 전에는 호재로 쓰지 않는다. `구상/검토 → 계획 발표 → 공식 확정(고시) → 착공 → 준공` 어디인지 명시한다.
- 정비사업은 `구역지정 → 조합설립 → 사업시행인가 → 관리처분인가 → 이주/철거 → 착공 → 준공` 중 현재 단계와 근거 문서를 남긴다.
- "예비타당성", "추진 검토", "공약" 단계는 확정이 아니다. 무산/지연 이력도 함께 조사한다.

## 9. 온라인 임장의 한계 (반드시 리포트에 구분 표기)

| 온라인으로 확인 가능 | 온라인으로 확인 어려움 (현장 확인 항목으로) |
|---|---|
| 가격, 거래량, 교통, 지도, 학교, 공원, 개발계획, 정비사업, 뉴스, 인프라, 건축물 정보 | 층간소음, 실제 소음, 냄새, 이웃 분위기, 관리 상태, 실제 일조, 실제 조망, 주차 체감, 단지 내 분위기, 밤길 분위기 |

## 10. 금지 목록 (전체)

1. 검색 결과 첫 번째 글만 보고 결론 내리기
2. 블로그 하나를 근거로 지역 평가
3. 부동산 유튜브의 전망을 사실처럼 작성
4. 개발 계획을 확정된 호재로 표현
5. 호가를 실거래가로 표현
6. 실거래가 하나만으로 가격 평가
7. 오래된 뉴스만으로 현재 상황 판단
8. 출처 없는 숫자 생성
9. 확인하지 않은 정보를 추정해서 작성
10. 로드뷰에서 확인할 수 없는 것을 확인했다고 주장
11. 이미지 출처 누락
12. 검색 결과의 광고성 콘텐츠를 객관적 정보로 취급
13. 모든 지역에 동일한 평가 기준을 강제로 적용
14. 점수만 보여주고 산정 근거를 공개하지 않기
15. "무조건 오른다", "무조건 사야 한다" 같은 표현 사용
16. 리포트에 실제 확인하지 않은 URL을 지어 넣기

## 11. 리포트 필수 구성 (검증 관점)

- Bull Case와 Bear Case를 동일 비중으로 작성한다.
- "가장 중요한 미확인 변수"(공개 데이터로 확정할 수 없는 핵심 변수)를 별도로 명시한다.
- 최종 판단(`매수 고려 / 적극 검토 / 관망 / 비추천`)에는 근거 3~5개를 붙이고, 투자 권유 표현을 쓰지 않는다.
- 중요한 사실에는 출처를 `기관명 | 자료명 | 기준일 | URL` 형태로 남긴다.
  특히 가격, 거래량, 정비사업, 개발계획, 교통계획, 학교, 인구, 규제, 정책, 뉴스에는 출처가 없으면 안 된다.
