# HTML 리포트 가이드

최종 산출물은 "부동산 초보자가 10~20분 안에 지역을 이해할 수 있는 리서치 대시보드"다.
단순 문서가 아니라 의사결정 도구로 만든다.

## 1. 파일 규약

- 경로: `reports/<대상>-온라인-임장-<YYYY-MM-DD>.html` (공백은 `-`로 치환)
- 단일 파일로 완결: CSS와 JS는 인라인, 차트는 SVG 직접 작성, 외부 서버 요청 없음
- 파일을 열면 바로 리포트가 보여야 한다
- 시작점: `templates/report-template.html`을 읽고 구조와 컴포넌트를 재사용한다.
  템플릿의 모든 수치와 문구는 자리표시자다. 조사 데이터로 완전히 교체한다.

## 2. 디자인 원칙

- 모바일/PC 반응형, 가독성 최우선, 흰색 배경, 카드 기반 UI, 충분한 여백
- 중요한 숫자는 크게, 긴 문단은 최소화(3~4문장 넘으면 나눈다), 표와 차트를 적극 활용
- 색상은 의미가 있을 때만 쓴다 (긍정 초록, 위험 빨강, 주의 주황, 정보 파랑)
- 위험은 명확하게 표시하고, 모든 데이터에 기준일과 출처 링크를 단다

## 3. 리포트 구조 (기본 24섹션)

지역 특성에 따라 추가하거나 제거한다. 데이터가 없는 섹션은 만들지 말고 한계에 기록한다.

1. Cover (제목, 조사 기준일)
2. 한 줄 결론
3. 핵심 지표 카드 (5~8개)
4. 이 지역을 한눈에 이해하기
5. 지도 / 위치 (SVG 개념도 + 지도 딥링크)
6. 교통
7. 생활 인프라
8. 교육
9. 주거 환경 (단지 조사면 단지 상세)
10. 실거래가
11. 가격 추이
12. 전세 / 월세
13. 주변 단지 비교
14. 개발 / 정비사업
15. 호재
16. 악재
17. 리스크
18. Bull Case
19. Bear Case
20. 초보자가 놓치기 쉬운 부분
21. 현장 방문 체크리스트
22. 최종 판단
23. 조사에 사용한 출처
24. 데이터 기준일 / 한계

## 4. 섹션별 필수 요건

- **Cover**: `[대상] 온라인 임장 리포트` + `조사 기준일: YYYY-MM-DD`
- **한 줄 결론**: judge.one_line. 장점과 한계가 한 문장에 함께 담기게 쓴다.
- **핵심 지표 카드**: 실거래가, 평당가, 역 도보, 준공연도, 세대수, 전세가율, 최고가 대비, 종합 판단 중 5~8개.
  각 카드에 기준일을 작게 표기한다. 점수를 쓰면 산정 근거를 공개한다.
- **지도/위치**: 무단 캡처 금지. 직접 그린 SVG 개념도(역, 학교, 마트, 대상의 상대 위치와 도보 시간)와
  지도 서비스 딥링크(예. `https://map.naver.com/p/search/방배동`, `https://map.kakao.com/?q=방배동`)를 함께 제공한다.
- **실거래가**: 표(계약일, 평형/전용, 층, 가격)로 싣고 실거래/호가/추정가를 구분한다. 출처는 국토부 기준을 우선한다.
- **가격 추이**: 데이터가 있을 때만 SVG 라인 차트를 그린다. 데이터 없는 장식용 차트는 금지다. 축과 단위, 기준일을 표기한다.
- **주변 단지 비교**: 비교표(가격, 평당가, 연식, 세대수, 역거리, 전세가율) + "왜 가격 차이가 나는가" 해설.
- **개발/정비사업**: 사업별 진행 단계를 타임라인 컴포넌트로 표시하고 "확정/진행/계획/검토"를 구분한다.
- **호재/악재/리스크**: 각 항목에 상태 배지(확정~확인 필요)를 붙인다. 리스크는 심각도(높음/중간/낮음)를 표시한다.
- **Bull/Bear**: 나란히 배치해 같은 비중임을 시각적으로도 보여준다. 각 논거에 근거(basis)를 작게 붙인다.
  바로 아래에 "가장 중요한 미확인 변수"(judge.key_unknowns)를 배치한다.
- **초보자가 놓치기 쉬운 부분**: 이 지역 특유의 함정(예. 언덕, 배정 변동 가능성, 선반영된 기대감)을 3~5개.
- **현장 방문 체크리스트**: 체크박스 목록. 기본 항목(템플릿 참고) + 이번 조사에서 나온 field_check 항목을 병합한다.
  judge.field_focus는 "최우선 확인"으로 강조한다.
- **최종 판단**: `매수 고려 / 적극 검토 / 관망 / 비추천` 4개 칩 중 하나를 활성화하고 근거 3~5개, who_fits,
  협상 관점(추정 명시)을 싣는다. 투자 권유 표현은 금지다.
- **출처**: `기관명 | 자료명 | 기준일 | URL` 형식의 번호 목록. 본문에서는 `<sup><a href="#src-N">[N]</a></sup>`로 참조한다.
  조사에서 실제 확인한 URL만 넣는다. 신뢰도 등급(A~E) 배지를 붙인다.
- **한계**: 온라인으로 확인하지 못한 것, 출처 간 충돌, 로드뷰 미실시 여부 등을 숨기지 않고 기록한다.

## 5. 용어 설명

전문 용어가 처음 나오면 `.term` 박스로 바로 설명한다. 정의는 `real-estate-glossary.md`를 따른다.
리포트 전체를 읽으면 초보자가 자연스럽게 용어를 배울 수 있어야 한다.

## 6. QA 체크리스트 (저장 후 반드시 수행)

### Content QA
- [ ] 중요한 주장에 출처가 있는가?
- [ ] 숫자가 서로 충돌하지 않는가? (충돌하면 설명이 있는가)
- [ ] 날짜가 오래되지 않았는가? 기준일이 표기됐는가?
- [ ] 호가와 실거래를 구분했는가?
- [ ] 개발 계획과 확정을 구분했는가?
- [ ] 추정을 사실처럼 표현하지 않았는가?

### UX QA
- [ ] 첫 화면에서 결론을 이해할 수 있는가?
- [ ] 표가 너무 복잡하지 않은가?
- [ ] 긴 문단이 없는가?
- [ ] 모바일에서 깨지지 않는가? (가로 스크롤은 표/차트 컨테이너 안에서만)
- [ ] 이미지/차트가 적절한 위치에 있는가?
- [ ] 링크가 작동하는가? (실제 확인한 URL인가)

### Investment QA
- [ ] Bull Case가 있는가?
- [ ] Bear Case가 있는가?
- [ ] 가장 큰 리스크가 명시됐는가?
- [ ] 비교군이 있는가?
- [ ] 현재 가격에 대한 판단 근거가 있는가?
- [ ] 현장 방문 시 확인할 사항이 있는가?

QA 에이전트를 쓸 경우 모델은 sonnet이면 충분하다. 프롬프트 예시:
"`<리포트 절대경로>` 파일을 Read로 열고, `<SKILL_DIR>/references/html-report-guide.md`의 QA 체크리스트 3종으로 검수해라.
항목별 통과 여부와 구체적 수정 제안을 보고해라. 특히 출처 없는 숫자, 호가/실거래 혼용, 확정/계획 혼용을 찾아라."

## 7. 최종 사용자 메시지

리포트 완성 후 사용자에게는 아래 형식으로 간결하게 알린다. 세부 내용은 리포트로 넘긴다.

```
온라인 임장을 완료했습니다.

📍 대상: 서울 서초구 방배동
📊 조사 기준일: 2026-08-27

핵심 결론:
(한 줄 결론)

주요 발견:
- (발견 1)
- (발견 2)
- (발견 3)

⚠️ 가장 중요한 리스크:
(top risk)

📄 리포트:
./reports/방배동-온라인-임장-2026-08-27.html
```
