# 지도와 임장 동선 가이드

리포트에 실제 좌표 기반 지도 두 장을 넣는다. 하나는 대표 단지가 어디에 있는지 보여주는 **위치 지도**이고,
다른 하나는 현장 임장 때 걸을 순서를 보여주는 **동선 지도**다. 둘 다 `scripts/build_map.py`로 만든다.

## 1. 왜 이 방식인가

- 네이버/카카오 지도 화면 캡처는 이용약관 문제로 쓰지 않는다. 대신 OpenStreetMap(ODbL) 벡터 데이터로 SVG를 직접 그린다.
  출처 표기 `© OpenStreetMap contributors (ODbL)`를 지도 안과 캡션에 남기면 재배포할 수 있다.
- SVG는 리포트 HTML 안에 인라인으로 들어간다. 리포트를 열 때 외부 서버 요청이 없다는 규칙을 지킨다.
- 실제 길찾기와 로드뷰는 지도 앱 딥링크로 넘긴다. 카카오맵 지점 링크와 로드뷰 링크, 구글 지도 도보 다중 경유 링크를 스크립트가 만들어 준다.

## 2. 절차 (STEP 6에서 오케스트레이터가 직접 수행)

1. **좌표 후보 찾기.** 대표 단지, 배정 초등학교, 공원, 가까운 역, 출발 지점의 OSM 객체를 찾는다.
   ```
   python3 <SKILL_DIR>/scripts/build_map.py find --around 37.399,126.937 --radius 1500 "삼성래미안|롯데캐슬|샘모루"
   python3 <SKILL_DIR>/scripts/build_map.py geocode "안양시 동안구 비산동 샘모루초등학교"
   ```
   - 단지는 `landuse=residential` 다각형(way)을 고른다. 경계가 그려져 지도에 단지 영역이 보인다.
   - 이름이 같은 다른 단지를 조심한다 (예. "안양동 삼성래미안"과 "비산 삼성래미안"). 리포트에 적힌 주소와 동네가 맞는지 확인한다.
   - 한 단지가 여러 블록 다각형이면 점을 여러 개 만들고 `group`을 카드 id로 맞춘다. 색과 링크가 공유된다.
   - OSM에 없는 단지는 지어내지 않는다. `geocode` 결과의 좌표를 `lat`/`lon`으로 넣고 `source`에 출처를 적거나, 지도에서 빼고 한계에 적는다.
2. **동선 정하기.** 동선은 리포트의 현장 체크 항목을 실제로 확인할 수 있는 순서로 짠다.
   - 출발과 도착은 대중교통으로 닿는 곳(역, 큰 정류장)으로 한다. 역이 멀면 `optional` 구간으로 역까지 거리를 계산해 보여준다.
   - 단지 지점은 단지 중심이 아니라 단지 앞 공공 지점(버스 정류장, 교차로)을 `access`로 준다. 경로가 단지 내부 사유지를 통과하지 않게 하기 위해서다.
   - 학교처럼 들렀다 가야 하는 곳은 `via`로 넣는다. 번호가 붙지 않고 경로만 지나간다.
   - 공원처럼 지나가며 보는 곳은 `"on_path": true`를 준다. 앞뒤 지점을 잇는 경로 위에서 가장 가까운 점에 찍고, 그런 경로가 없으면 앞 지점에서 들어가는 길이 경계에 처음 닿는 입구에 찍는다. 중심점에 찍으면 들어갔다 되돌아 나오는 갈고리가 그려진다.
   - `"access_edge_toward": "<지점 id>"`는 지점 다각형에서 그 지점 쪽 꼭짓점을 접근점으로 쓴다.
   - 같은 길을 왕복하는 지점(예. 큰길을 따라 갔다가 되돌아오는 교차로)은 넣지 않는다. 그 지점에서 할 일을 근처 다른 지점으로 옮길 수 있으면 옮긴다.
   - 번호 마커가 24px 안으로 붙으면 스크립트가 서로 밀어내고 실제 위치까지 지시선을 긋는다.
   - 한 바퀴 2~3시간 안쪽으로 짠다. 낮(일조, 통학로)과 저녁(주차, 귀갓길)에 봐야 할 항목이 갈리면 리포트 표에 시간대를 적는다.
   - 사용자의 직장이나 통근 단서가 있으면(프로젝트 CLAUDE.md 포함) 출발 지점 정류장에서 출근 방향 노선을 확인하는 항목을 넣는다.
3. **스펙 작성과 빌드.** 아래 형식의 JSON을 스크래치 디렉토리에 쓰고 빌드한다. 네트워크 응답은 `cache_dir`에 캐시된다.
   ```
   python3 <SKILL_DIR>/scripts/build_map.py build spec.json
   ```
   출력: `<out_dir>/<map id>.svg`(인라인용 SVG), `<out_dir>/result.json`(지점 좌표, 구간별 거리/시간, 앱 링크).
4. **리포트에 넣기.** 템플릿의 `#map`(위치 지도)과 `#route`(동선 지도) 컴포넌트에 SVG를 그대로 붙이고,
   `result.json`의 구간 표와 링크를 채운다. 지도 숫자(거리, 분)는 `result.json` 값만 쓴다.
   `.map-view`의 `data-focus`는 모바일에서 처음 보일 지점이다. 위치 지도는 대표 단지 중심, 동선 지도는 출발 지점 쪽(출발점과 첫 지점 사이, 출발점에 더 가깝게)으로 잡는다. 걷기 시작하는 곳이 첫 화면에 보여야 해서다.
5. **검수.** 브라우저에서 데스크톱(약 1000px)과 모바일(390px) 폭으로 열어 라벨 겹침, 잘림, 확대 버튼, 단지 클릭 이동을 확인한다.

## 3. 스펙 형식

```json
{
  "out_dir": "<스크래치>/map/out",
  "cache_dir": "<스크래치>/map/cache",
  "points": [
    {"id": "cx-1", "label": "비산삼성래미안", "kind": "complex", "osm": "way/381466612", "href": "#cx-1", "search": "비산삼성래미안"},
    {"id": "cx-2a", "group": "cx-2", "label": "평촌엘프라우드 1단지", "kind": "complex", "osm": "way/1262777321", "href": "#cx-2"},
    {"id": "school", "label": "샘모루초", "kind": "school", "osm": "way/381466614"},
    {"id": "start", "label": "비산사거리", "kind": "access", "osm": "node/437298540"},
    {"id": "acc-1", "label": "단지 앞 정류장", "kind": "access", "osm": "node/357909977"},
    {"id": "st-1", "label": "범계역", "kind": "station", "osm": "node/6035746705"}
  ],
  "route": {
    "stops": [
      {"point": "start", "label": "비산사거리"},
      {"point": "cx-1", "access": "acc-1", "label": "비산삼성래미안", "via": ["school"]}
    ],
    "optional": [{"from": "start", "to": "st-1", "note": "역에서 오는 경우"}]
  },
  "maps": [
    {"id": "overview", "fit": ["cx-1", "cx-2a", "school", "start"], "pad_m": 200, "width": 760,
     "layers": ["water", "parks", "complexes", "roads", "rail"], "route": false, "optional_legs": true,
     "show": ["cx-1", "cx-2a", "school"]},
    {"id": "route", "fit": ["start", "cx-1", "school"], "pad_m": 160, "width": 760, "max_aspect": 1.05,
     "layers": ["water", "parks", "buildings", "complexes", "roads", "rail"], "route": true,
     "show": ["cx-1", "cx-2a", "school"]}
  ]
}
```

| 필드 | 뜻 |
|---|---|
| `kind` | `complex`(단지 영역과 이름), `school`, `park`, `station`, `poi`(아이콘과 이름), `access`(그리지 않는 접근 지점) |
| `osm` 또는 `lat`/`lon` | 좌표 출처. `osm`이 우선이다. 직접 좌표를 쓰면 `source`를 반드시 적는다 |
| `href` | 지도에서 단지를 눌렀을 때 이동할 카드 앵커 |
| `show` | 그 지도에 그릴 지점. `fit`은 지도 범위를 정하는 지점 |
| `route` / `optional_legs` | 번호 동선을 그릴지, 역까지의 선택 구간(점선, 지도 밖이면 가장자리 화살표)을 그릴지 |
| `layers` | `water`, `parks`, `buildings`, `complexes`(맥락용 다른 단지), `roads`, `rail`. 건물은 동선 지도처럼 좁은 범위에만 쓴다 |

## 4. 숫자를 쓸 때의 규칙

- 도보 거리는 OSM 보행망의 최단 경로이고, 시간은 분당 75m(시속 4.5km) 가정이다. 신호 대기, 경사, 실제 출입 가능 여부는 반영하지 않는다. 리포트에 이 전제를 함께 쓴다.
- `steps_m`이 0보다 크면 계단 구간이 있다는 뜻이다(OSM 표기 기준). 유모차, 휠체어 동선과 관련되면 표에 적는다.
- `inside_complex_m`이 0보다 크면 경로가 다른 단지 내부를 지난다는 뜻이다. "단지 출입 가능 여부 현장 확인"을 붙인다.
- `snap_m`이 60m를 넘는 지점은 접근 지점을 잘못 고른 것이다. 더 가까운 공공 지점으로 바꾼다.
- 좌표의 상태 배지는 `참고`다. OSM은 커뮤니티 편집 데이터다(출처 등급 E, 위치 참고 용도). 단지 경계와 배정 학교 같은 사실은 지도 모양으로 판단하지 않는다.
- 경사, 소음, 야간 조도처럼 지도로 알 수 없는 것을 지도 근거로 쓰지 않는다. 현장 체크 항목으로 둔다.
